# Sets: question sets, the editor and new question types

Branch `wip/sets`. Migration `0011_sets_library.sql` (three tables and five columns on `question_sets`).

## Bug fixed

| What was wrong | What a person sees now | Where | How it was verified |
|---|---|---|---|
| When a mode needed choices, a flashcard or typed question turned into multiple choice borrowed wrong options of another kind from the set (for example "34%" beside a definition), which could give the answer away. | Wrong options are always the same kind as the right one: a number beside numbers, a short name beside short names, a definition beside definitions. A question with too few of its kind is typed instead, or left out with a reason. | `packages/engine/src/questions/adapt.ts` (`answerShape`, `distractorsFor`) | New cases in `packages/engine/test/grade.test.ts` (fail on the old code, pass now). The 14 seeded extras tests whose dealt questions changed were updated one by one (`extras-pack-glow-tag`, `-gold-rush`, `-lantern-guard`, `-lantern-trail`, `-night-market`, and scenarios in `test/extras-scenarios/` for big-catch, code-breakers, corner-shop, festival-workshop, gloom-giant, gold-rush, lantern-trail): each now sets up the situation it tests explicitly (or picks a seed where it arises) rather than relying on luck. `vitest run packages/engine/test/extras-` 6,782 passed. |
