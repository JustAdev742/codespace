# Mode Studio: people make their own game modes (`modestudio`)

> Mode Studio is now **Game Maker** (`/game-maker`; `/mode-studio` links redirect there), with game
> code and rules on top of what is described here: see [gamecode.md](gamecode.md). The page names
> below are as they were when this was written.

A made game is a **blueprint**: data built only from parts Ludora provides, never code. One
interpreter runs every blueprint that passes the check. Migration **0021** (`0021_blueprints.sql`)
adds the `blueprints` table.

How it fits: `packages/shared/src/blueprint.ts` (schema, check, rules in words, starting points) →
`packages/engine/src/modes/made-game/index.ts` (`blueprintMode(bp)` returns an ordinary `GameMode`
with id `made-game`) → rooms carry the blueprint (`RoomInit.madeGame`) and build the mode from it
(`resolveGameConfig` takes an optional `mode`, an additive change) → screens in
`web/src/features/room/modes/made-game*.tsx`, the studio in `web/src/features/modestudio/`.
The interpreter is not in `MODES`: without its blueprint it is not a game, so the catalogue, the 30
built-in modes and their conformance tests are untouched; the fuzz test below is its conformance test.

## Not done or not verified

- 3D scenes exist for races and climbs only; the other five kinds are 2D (the check says so).
- The live test room takes at most 20 bots (the room's own cap), so 40 players were measured on the
  dev page, not in a live room.
- The AI panel was not exercised in a browser; the task is tested on the server with a model answer.
- Night theme was not checked separately by axe (the e2e runs in the browser's default scheme).
- “Host again” from a report of a made game does not reopen the made game (it needs the blueprint).
